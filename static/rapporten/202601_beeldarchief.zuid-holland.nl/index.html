01 Algemene knelpunten

#1 - Zoomfunctionaliteit niet beschikbaar

Impact: Groot Type: Techniek WCAG: 1.4.4 EN: 9.1.4.4

Op alle pagina’s is in het <head>-element van de HTML-code maximum-scale=1 aanwezig.

Deze code zorgt ervoor dat een bezoeker in sommige browsers niet kan inzoomen.

Oplossing:

Verwijder deze code.

#2 - Focusindicator onzichtbaar

Impact: Groot Type: Techniek WCAG: 2.4.7 EN: 9.2.4.7

Op alle pagina’s van deze website is de standaard toetsenbordfocusindicator verwijderd van interactieve elementen. Er is geen alternatief focusindicator toegevoegd.

De toetsenbordfocus moet altijd zichtbaar zijn op interactieve elementen, zoals links, knoppen en invoervelden die focus kunnen krijgen via het toetsenbord. Bezoekers die met het toetsenbord navigeren moeten duidelijk kunnen zien waar zij zich bevinden op de pagina..

Oplossing:

Zorg ervoor dat de toetsenbordfocus zichtbaar is op alle interactieve elementen. Op deze pagina staat een instructie om focuszichtbaarheid te testen: https://www.properaccess.nl/blog/hoe-test-ik-focus-zichtbaarheid/.

#3 - Link zonder toegankelijke naam

Impact: Groot Type: Techniek WCAG: 4.1.2, 2.4.4 EN: 9.4.1.2, 9.2.4.4

In de header van de website functioneren drie horizontale lijnen als een link die een navigatiemenu opent. Deze link heeft geen toegankelijke naam.

Voor gebruikers van een schermlezer is daardoor onduidelijk wat de bestemming of de functie van de link is. Dit probleem hangt ook samen met succescriterium 2.4.4, omdat het doel van de link niet duidelijk is.

Oplossing:

Geef de link een toegankelijke naam, bijvoorbeeld met linktekst, een aria-label of een andere geschikte techniek.

Op deze pagina staat een instructie om toegankelijke namen te testen: https://www.properaccess.nl/blog/sc-4-1-2-wat-betekent-naam-rol-waarde/.

#4 - Linkdoel is onbekend

Impact: Medium Type: Content / Techniek WCAG: 1.1.1, 2.4.4, 4.1.2 EN: 9.1.1.1, 9.2.4.4, 9.4.1.2

In de header van de website staat een icoon met drie horizontale lijnen dat werkt als een link die een navigatiemenu opent. Deze link heeft geen toegankelijke naam. Het icoon heeft geen tekstalternatief, waardoor de bestemming van de link onbekend is voor een schermlezer.

Oplossing:

Voorzie de link van de inhoud die het doel beschrijft. Dat kan bijvoorbeeld door::

  • Tekst toevoegen aan het <a>-element: voeg beschrijvende tekst toe binnen het element.
  • aria-label gebruiken: voeg het aria-label-attribuut toe met een beknopte beschrijving van de bestemming van de link.

Zorg ervoor dat alle links een duidelijk linkdoel hebben.

#5 - Status mobiel menu ontbreekt

Impact: Groot Type: Techniek WCAG: 4.1.2 EN: 9.4.1.2

In de header van de website opent de link met drie horizontale lijnen een navigatiemenu. Een schermlezer geeft niet door of het menu is geopend of gesloten.

Wanneer een submenu aanwezig is, moet het trigger element, zoals een menu knop of een link, aangeven of het submenu zichtbaar of verborgen is. Zo kan hulpsoftware deze informatie correct voorlezen.

Oplossing:

Gebruik het aria-expanded-attribuut op de knop of de link die het submenu opent.

#6 - Linknaam beschrijft functie niet

Impact: Groot Type: Techniek WCAG: 2.4.4 EN: 9.2.4.4

In de header van de website staat in het mobiele menu een link met een “X”-icoon. Deze link sluit het menu, maar de toegankelijke naam is “Open het menu”. De naam beschrijft de functie niet correct.

Gebruikers van een schermlezer weten daardoor niet wat deze link precies doet.

Oplossing:

Voeg tekst toe die deze link goed beschrijft.

#7 - Onvoldoende kleurcontrast van icoon op link

Impact: Groot Type: Techniek WCAG: 1.4.11 EN: 9.1.4.11

De link met een “X”-icoon in het mobiele menu heeft onvoldoende kleurcontrast tussen het lichtgrijze icoon (#CCCCCC) en de witte achtergrond. De contrastratio van 1,6:1 is te laag.

Het icoon is niet voor iedereen goed zichtbaar.

Dit probleem komt ook voor bij het “X”-icoon in het paneel “Jouw reactie op dit item” op de volgende pagina’s: https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3567\&title=brandbestrijding-bij-een-bombardement-van-dordrecht\&title=Brandbestrijding-bij-een-bombardement-van-Dordrecht en https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3568\&title=elektrisch-gemaal-donk-aan-het-rietveld-23-in-arkel\&title=Elektrisch-gemaal-Donk-aan-het-Rietveld-2/3-in-Arkel. Dit paneel wordt geopend via de link “reageer op dit item”.

Het probleem is ook aanwezig op de volgende pagina’s: https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3814\&title=aardammerbrug-en-korenmolen-de-vlinder-in-ter-aar en https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3818\&title=een-duiker-voert-waarschijnlijk-een-onderwaterinspectie-uit-bij-een-brug-of-een-sluis-de-foto-is-gemaakt-tussen-1920-en-1940. Hier gaat het om de panelen die worden geopend via de links “bekijk vergroting” en “reageer op dit item”.

Oplossing:

Zorg voor een minimaal contrast van 3,0:1.

#8 - Focusvolgorde onjuist na sluiten mobiel menu

Impact: Groot Type: Techniek WCAG: 2.4.3 EN: 9.2.4.3

In de header van de website opent de link met drie horizontale lijnen het mobiele menu. Nadat het menu is gesloten, keert de toetsenbordfocus niet terug naar het element dat het menu heeft geopend of naar het eerstvolgende logische element in de focusvolgorde van de pagina.

In plaats daarvan komt de toetsenbordfocus eerst terecht op onzichtbare interactieve elementen van het gesloten navigatiemenu. Daarna verplaatst de focus zich naar het eerste interactieve element op de pagina.

Dit probleem komt ook voor bij het paneel “Jouw reactie op dit item” op de volgende pagina’s: https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3567\&title=brandbestrijding-bij-een-bombardement-van-dordrecht\&title=Brandbestrijding-bij-een-bombardement-van-Dordrecht en https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3568\&title=elektrisch-gemaal-donk-aan-het-rietveld-23-in-arkel\&title=Elektrisch-gemaal-Donk-aan-het-Rietveld-2/3-in-Arkel. Dit paneel wordt geopend via de link “reageer op dit item”.

Het probleem is ook aanwezig op de volgende pagina’s: https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3814\&title=aardammerbrug-en-korenmolen-de-vlinder-in-ter-aar en https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3818\&title=een-duiker-voert-waarschijnlijk-een-onderwaterinspectie-uit-bij-een-brug-of-een-sluis-de-foto-is-gemaakt-tussen-1920-en-1940. Hier gaat het om de panelen die worden geopend via de links “bekijk vergroting” en “reageer op dit item”.

Oplossing:

Zorg ervoor dat de focus na het sluiten van het menu terugkeert naar het element waarmee het menu is geopend. Daarnaast moet alleen zichtbare elementen toetsenbordfocus kunnen krijgen en moet de focusvolgorde logisch en voorspelbaar zijn.

#9 - Lijstitems staan niet binnen een lijst

Impact: Medium Type: Techniek WCAG: 1.3.1 EN: 9.1.3.1

In de footer van de website staat onder de kop “Over ons” een groep links. Deze links zijn geplaatst in <li>-elementen, maar het container element <ul> ontbreekt. Lijstitems moeten binnen het ul-element staan, zodat de onderlinge relatie en groepering correct wordt doorgegeven aan hulpsoftware.

Meer informatie over het belang van correcte HTML-lijsten is te vinden op: https://www.properaccess.nl/blog/waarom-correcte-html-lijsten-het-verschil-maken-in-toegankelijkheid/.

Oplossing:

Zorg ervoor dat alle opsommingen correct zijn gemarkeerd in de HTML-structuur.

#10 - strong-element wordt gebruikt voor opmaak

Impact: Klein Type: Content WCAG: 1.3.1 EN: 9.1.3.1

In de footer van de website wordt het <strong>-element gebruikt voor opmaak. De linktekst “Picture Pack” is in een <strong>-element geplaatst om deze vet weer te geven.

Het <strong>-element heeft een semantische betekenis en geeft aan dat tekst extra nadruk heeft. Het element is niet bedoeld om alleen een visueel effect, zoals vetgedrukte tekst, weer te geven.

Oplossing:

Verwijder de <strong>-elementen die alleen voor opmaak worden gebruikt. Gebruik CSS om tekst vet te maken. Of maak gebruik van het <b>-element.

#11 - Links alleen door kleur te onderscheiden

Impact: Medium Type: Techniek WCAG: 1.4.1 EN: 9.1.4.1

In de footer is kleur het enige verschil tussen links en statische tekst. De links zijn daardoor alleen herkenbaar door kleurverschil.

Dit kan een probleem zijn voor kleurenblinde of slechtziende bezoekers. Zij kunnen kleuren mogelijk niet onderscheiden en herkennen daardoor niet dat er een link in de tekst staat.

Oplossing:

Kleur mag worden gebruikt om links te onderscheiden van statische tekst, mits aan de volgende voorwaarden voldaan:

  • het contrast tussen de linktekst en de omringende tekst is hoger dan 3:1, en
  • voeg een tweede visuele indicator toe bij hover, zoals een onderstreping of een verandering van de achtergrondkleur.

#12 - Tekst deels onleesbaar bij inzoomen

Impact: Groot Type: Techniek WCAG: 1.4.4, 1.4.10 EN: 9.1.4.4, 9.1.4.10

Wanneer de pagina’s van de website worden bekeken met een schermresolutie van 1280 bij 1024 pixels en ingezoomd tot 200%, verdwijnt de volgende tekst in de footer: “Copyright Historische beeldbank provincie Zuid-Holland 2026 | powered by Picture Pack”. Deze tekst wordt bedekt door een sticky footer.

Dit probleem is ook aanwezig bij inzoomen tot 400% bij dezelfde schermresolutie. In dat geval is de tekst gedeeltelijk niet zichtbaar.

Oplossing:

Zorg dat alle inhoud zichtbaar en leesbaar blijft wanneer de pagina wordt ingezoomd tot 200% en 400% bij een schermresolutie van 1280 bij 1024 pixels.

#13 - Toetsenbordfocus is bedekt

Impact: Advies Type: Techniek WCAG: 2.4.11

Op de pagina’s van de website wordt bij het verkleinen van het scherm een deel van de pagina-inhoud bedekt door een sticky footer. Interactieve elementen kunnen nog steeds toetsenbordfocus krijgen, maar wanneer het probleem met de zichtbare focusindicator onder succescriterium 2.4.7 is opgelost, zal de focusindicator achter deze sticky footer verdwijnen.

Hierdoor kunnen bezoekers die met het toetsenbord navigeren niet zien waar de toetsenbordfocus zich bevindt.

Oplossing:

Zorg ervoor dat de sticky sectie geen interactieve elementen of hun focusindicatoren bedekt. Dit kan bijvoorbeeld door de z-index aan te passen, elementen te herpositioneren of de header/footer dynamisch te verkleinen op kleinere schermen.

#14 - title-element bevat geen tekst

Impact: Medium Type: Content WCAG: 2.4.2 EN: 9.2.4.2

Het <title>-element op deze pagina is leeg.

Dit element moet op elke pagina aanwezig zijn en een beknopte, unieke tekst bevatten die de inhoud van de pagina beschrijft. Bij voorkeur wordt deze tekst aangevuld met de naam van de organisatie. De tekst wordt getoond in de tab van de browser. Een duidelijke paginatitel maakt het eenvoudiger om tussen verschillende pagina’s te navigeren.

Dit probleem komt ook voor op de volgende pagina’s.: https://beeldarchief.zuid-holland.nl/misc.pp?code=contact, https://beeldarchief.zuid-holland.nl/misc.pp?code=toegankelijkheidsverklaring, https://beeldarchief.zuid-holland.nl/misc.pp?code=rechten, https://beeldarchief.zuid-holland.nl/misc.pp?code=over-de-beeldbank, https://beeldarchief.zuid-holland.nl/misc.pp?code=353, en https://beeldarchief.zuid-holland.nl/misc.pp?code=privacyverklaring.

Oplossing:

Plaats een tekst in het <title>-element die de inhoud van de pagina beschrijft.

#15 - Suggestielijst bij zoekbalk is ontoegankelijk

Impact: Groot Type: Techniek WCAG: 1.3.1, 4.1.2 EN: 9.1.3.1, 9.4.1.2

De zoekbalk toont tijdens het typen suggesties in een uitklaplijst en functioneert daarmee als een combobox. De benodigde rollen en attributen ontbreken. Daardoor is dit element niet toegankelijk voor gebruikers van een schermlezer.

Dit probleem komt ook voor op de volgende pagina: https://beeldarchief.zuid-holland.nl/search.pp.

Oplossing:

Voeg de benodigde rollen en attributen toe om de zoekbalk toegankelijk te maken, bijvoorbeeld:

  • role="combobox": voeg dit attribuut toe aan het invoerveld om aan te geven dat het een keuzelijst is.
  • aria-expanded: voeg dit attribuut toe aan het invoerveld om de status van de suggestielijst aan te geven. Stel aria-expanded="true" in als de lijst zichtbaar is en aria-expanded="false" wanneer deze verborgen is.
  • er zijn meer attributen die nodig zijn om dit element toegankelijk te maken. Zie https://www.w3.org/WAI/ARIA/apg/patterns/combobox/.

Deze attributen helpen hulpsoftware om de zoekbalk correct te herkennen en te gebruiken als een keuzelijst.

#16 - Keuzelijst heeft geen toegankelijke naam

Impact: Medium Type: Techniek WCAG: 2.5.3, 4.1.2 EN: 9.2.5.3, 9.4.1.2

Op deze pagina staat naast het zoekveld een uitklaplijst (<select>-element) met het label “type”. De toegankelijke naam ontbreekt. Daardoor is de keuzelijst niet toegankelijk voor gebruikers van een schermlezer.

De eerste optie wordt gebruikt als pseudo-label. Dit label verdwijnt als de bezoeker een andere optie selecteert. Hierdoor kunnen bezoekers die gebruikmaken van spraaksoftware het element niet bedienen. Zij geven een commando door de zichtbare tekst uit te spreken.

Het label moet daarom permanent zichtbaar zijn én ook terugkomen in de toegankelijke naam van het element. Als de zichtbare tekst niet voorkomt in de toegankelijke naam die in de code staat, werkt het spraakcommando niet. Dit valt onder de succescriteria 2.5.3.

Oplossing:

Voeg een permanent zichtbaar label en een toegankelijke naam toe aan het <select>-element. Zorg dat de toegankelijke naam de zichtbare tekst bevat, bij voorkeur aan het begin van de naam. De toegankelijke naam mag gelijk zijn aan de zichtbare tekst.

#17 - Icoonknoppen hebben geen toegankelijke namen

Impact: Groot Type: Techniek WCAG: 4.1.2 EN: 9.4.1.2

Op deze pagina heeft de knop met een vergrootglas-icoon een onleesbaar teken in de toegankelijke naam. Er is geen tekst die een schermlezer kan voorlezen als toegankelijke naam. Daardoor is voor gebruikers van een schermlezer onduidelijk wat de bestemming of functie van de knop is.

Dit probleem komt ook voor op de volgende pagina: https://beeldarchief.zuid-holland.nl/search.pp.

Oplossing:

Voorzie de knoppen van een toegankelijke naam, bijvoorbeeld via knoptekst, een aria-label of een andere techniek. Op deze pagina staat een instructie om toegankelijke namen te testen: https://properaccess.nl/sc-4-1-2-wat-betekent-naam-rol-waarde/.

#18 - Onvoldoende kleurcontrast linktekst bij hover

Impact: Medium Type: Techniek WCAG: 1.4.3 EN: 9.1.4.3

Op deze pagina heeft de linktekst “alle items” bij hover onvoldoende kleurcontrast. De contrastratio is 3,8:1 en daarmee lager dan de vereiste 4,5:1 voor normale tekst.

Dit moet minimaal 4,5:1 zijn. Omdat het contrast niet voldoet aan de minimale eisen, kan de tekst ontoegankelijk zijn voor bezoekers met een visuele beperking.

Dit probleem komt ook voor bij de links onder de kop “Trefwoorden” op de volgende pagina: https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3567\&title=brandbestrijding-bij-een-bombardement-van-dordrecht\&title=Brandbestrijding-bij-een-bombardement-van-Dordrecht.

Oplossing:

Zorg ervoor dat het contrast ook bij hover minimaal 4,5:1 is.

#19 - Functionaliteit niet beschikbaar bij 400% zoom

Impact: Groot Type: Techniek WCAG: 1.4.10 EN: 9.1.4.10

Wanneer deze pagina wordt bekeken met een schermresolutie van 1280 bij 1024 pixels en ingezoomd tot 400%, is de uitklaplijst (<select>-element) met het label “type” naast het zoekveld niet zichtbaar en niet bedienbaar.

Oplossing:

Zorg ervoor dat alle functies nog werken wanneer de pagina wordt ingezoomd tot 400% bij een schermresolutie van 1280 bij 1024 pixels.

#20 - Onzichtbaar element krijgt toetsenbordfocus

Impact: Groot Type: Techniek WCAG: 2.4.3 EN: 9.2.4.3

Wanneer deze pagina wordt bekeken op kleinere schermen, bijvoorbeeld bij een schermresolutie van 1280 bij 1024 pixels en ingezoomd tot 400%, is de uitklaplijst (<select>-element) met het label “type” naast het zoekveld visueel verborgen. Daardoor komt de toetsenbordfocus terecht op een onzichtbaar interactief element.

De toetsenbordfocus mag niet terechtkomen op onzichtbare interactieve elementen. Als dit wel gebeurt, kan een bezoeker een element onbedoeld activeren en raakt de navigatie onvoorspelbaar.

Oplossing:

Zorg ervoor dat alleen zichtbare elementen toetsenbordfocus kunnen krijgen en dat de focusvolgorde logisch en voorspelbaar blijft.

#21 - Linknaam beschrijft linkdoel onvolledig

Impact: Advies Type: Techniek WCAG: 2.4.6 EN: 9.2.4.6

Dit punt is een advies en geen fout, maar het kan de toegankelijkheid van de website verbeteren.

Op deze pagina opent de link met de tekst “alle items” de pagina met alle zoekresultaten, maar de toegankelijke naam “alle items” beschrijft het linkdoel niet duidelijk.

Daardoor is het voor gebruikers van een schermlezer onduidelijk wat er gebeurt wanneer de link wordt geactiveerd.

Oplossing:

Voeg tekst toe die deze link goed beschrijft.

#22 - label-element niet gekoppeld aan invoerveld

Impact: Groot Type: Techniek WCAG: 1.3.1, 2.5.3, 4.1.2 EN: 9.1.3.1, 9.2.5.3, 4.1.2

Deze pagina bevat een formulier waarin de <label>-elementen niet expliciet zijn gekoppeld aan de bijbehorende invoervelden.

<label>-elementen moeten altijd zijn gekoppeld aan de bijbehorende invoervelden. Daardoor krijgt het invoerveld een toegankelijke naam en wordt het klikgebied van het label vergroot. Dit verbetert de toegankelijkheid en bruikbaarheid. Omdat het invoerveld geen toegankelijke naam heeft, valt deze bevinding ook onder succescriterium 4.1.2.

Wanneer de zichtbare tekst niet voorkomt in de toegankelijke naam, kan het element bovendien niet worden bediend met spraakbediening. Commando’s die zijn gebaseerd op de zichtbare tekst werken dan niet. Dit valt onder het succescriterium 2.5.3.

Dit probleem komt ook voor het filterpaneel op pagina https://beeldarchief.zuid-holland.nl/search.pp, bij de velden “Vanaf” en “Tot” onder de kop “Datum”.

Oplossing:

Koppel de <label>-elementen aan de bijbehorende invoervelden door het for attribuut op het <label>-element te gebruiken. In dit attribuut staat het id van het invoerveld waar het label bij hoort.

Zorg ervoor dat de zichtbare tekst voorkomt in de toegankelijke naam, bij voorkeur aan het begin.

#23 - autocomplete-attribuut ontbreekt bij invoervelden

Impact: Medium Type: Techniek WCAG: 1.3.5 EN: 9.1.3.5

Op deze pagina ontbreekt bij een formulier met invoervelden voor persoonsgegevens het autocomplete-attribuut. Het gaat om de velden: “Voornaam”, “Achternaam”, “E-mail”, “Telefoonnummer”.

Invoervelden voor persoonsgegevens, zoals achternaam, e-mailadres of telefoonnummer, moeten het autocomplete-attribuut bevatten. Dit stelt browsers en hulpsoftware in staat om gebruikers te ondersteunen, bijvoorbeeld door relevante velden automatisch in te vullen.

#34 - Problemen met toetsenbordfocus in filterpaneel

Impact: Groot Type: Techniek WCAG: 2.4.3, 2.4.11 EN: 9.2.4.3

Wanneer een bezoeker de pagina voor het eerst opent, is het paneel met filters standaard geopend. In dit paneel staat een knop met een pijl-icoon waarmee het paneel kan worden gesloten. Nadat de bezoeker het paneel sluit, verschijnt de link met de tekst “filters”. Wanneer de bezoeker deze link activeert en het paneel weer opent, komt de toetsenbordfocus niet in het paneel terecht.

Wanneer de pagina wordt ingezoomd en voor het eerst wordt geopend, is het filterpaneel ook standaard geopend. Bezoekers kunnen met het toetsenbord uit het paneel navigeren. De toetsenbordfocus verplaatst zich dan naar de onderliggende pagina, terwijl het paneel geopend blijft.

Het paneel overlapt interactieve elementen op de onderliggende pagina. Deze onderliggende elementen kunnen nog steeds toetsenbordfocus krijgen, ook al zijn ze niet zichtbaar door het paneel. Elementen die toetsenbordfocus krijgen, moeten zichtbaar zijn. Het toestaan van focus op verborgen elementen zorgt voor verwarring bij gebruikers van een toetsenbord of een schermlezer.

Oplossing:

Bij panelen zoals deze moet de toetsenbordfocus correct worden ingesteld. Wanneer het paneel actief is, moet de focus binnen het panel blijven en mag deze niet op de onderliggende pagina terechtkomen.

Dit kan op een van de volgende manieren worden opgelost:

1. Houd de focus binnen het paneel totdat het paneel wordt gesloten, bijvoorbeeld via de sluitknop of met de ESC-toets.
2. Sluit het paneel automatisch op het moment dat de toetsenbordfocus het panel verlaat.

Op deze pagina staat een instructie om de focusvolgorde te testen: https://properaccess.nl/hoe-test-ik-focusvolgorde/.

#41 - Betekenisvolle visuele informatie in video niet toegankelijk

Impact: Medium Type: Content WCAG: 1.2.3, 1.2.5 EN: 9.1.2.3, 9.1.2.5

In dat geval moet een audiobeschrijving worden toegevoegd die de visuele elementen in de video beschrijft, zoals namen, functies, logo’s en teksten.

#42 - canvas-element zonder tekstalternatief

Impact: Groot Type: Content / Techniek WCAG: 1.1.1 EN: 9.1.1.1

Op deze pagina opent de link “bekijk vergroting” het paneel “Inzoomen”. In dit paneel zijn <canvas>-elementen aanwezig, maar deze elementen hebben geen tekstalternatief.

Dit probleem komt ook voor op de volgende pagina: https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3818\&title=een-duiker-voert-waarschijnlijk-een-onderwaterinspectie-uit-bij-een-brug-of-een-sluis-de-foto-is-gemaakt-tussen-1920-en-1940.

Oplossing:

Zorg ervoor dat elk <canvas>-element altijd een tekstalternatief heeft dat de inhoud beschrijft. Dit kan bijvoorbeeld door de tekst in het element zelf op te nemen of door gebruik te maken van attributen, zoals title, aria-label of aria-labelledby.

Een <canvas>-element moet altijd een tekstalternatief hebben, zodat hulpsoftware toegang heeft tot de informatie.

Meer voorbeelden van toegankelijke<canvas>-implementaties zijn te vinden op:
https://www.html5accessibility.com/tests/canvas.html en https://pauljadam.com/demos/canvas.html.

#43 - Onjuiste toegankelijke rol bij knoppen

Impact: Groot Type: Techniek WCAG: 4.1.2 EN: 9.4.1.2

In het paneel “Inzoomen”, dat wordt geopend via de link “bekijk vergroting”, is een werkbalk met knoppen aanwezig, zoals een knop met een ‘+’-icoon. Deze knoppen hebben niet de juiste toegankelijke rol.

HTML-elementen hebben standaard een rol die aangeeft welke functie zij hebben. Hulpsoftware, zoals schermlezers, gebruikt deze rol om te bepalen hoe een element moet worden aangekondigd en bediend. Wanneer de rol niet correct is ingesteld, kan hulpsoftware het element niet goed herkennen.

Daarnaast hebben deze knoppen geen toegankelijke naam. Hierdoor is voor gebruikers van een schermlezer onduidelijk wat de bestemming of functie van de knop is.

Dit probleem komt ook voor op de volgende pagina: https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3818\&title=een-duiker-voert-waarschijnlijk-een-onderwaterinspectie-uit-bij-een-brug-of-een-sluis-de-foto-is-gemaakt-tussen-1920-en-1940.

Oplossing:

Gebruik voor deze bedieningselementen het <button>-element, zodat de juiste toegankelijke rol wordt toegepast.

Zorg er daarnaast voor dat elke knop een toegankelijke naam heeft, bijvoorbeeld via knoptekst, een aria-label of een andere geschikte techniek.

Op deze pagina staat een instructie om toegankelijke namen te testen: https://properaccess.nl/sc-4-1-2-wat-betekent-naam-rol-waarde/.

#44 - Knoppen niet toegankelijk via toetsenbord

Impact: Groot Type: Techniek WCAG: 2.1.1 EN: 9.2.1.1

In het paneel “Inzoomen”, dat wordt geopend via de link “bekijk vergroting”, is een werkbalk met knoppen aanwezig. Deze knoppen zijn niet met het toetsenbord te bedienen.

Wanneer een bezoeker met het toetsenbord navigeert, worden deze knoppen overgeslagen. Alle interactieve elementen, ook knoppen, moeten volledig te bedienen zijn met het toetsenbord.

Dit probleem komt ook voor op de volgende pagina: https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3818\&title=een-duiker-voert-waarschijnlijk-een-onderwaterinspectie-uit-bij-een-brug-of-een-sluis-de-foto-is-gemaakt-tussen-1920-en-1940.

Oplossing:

Zorg ervoor dat alle interactieve elementen, waaronder knoppen, te bedienen zijn met het toetsenbord. Activering moet mogelijk zijn met de Enter-, Return- of spatiebalktoets.

#45 - Onduidelijke linktekst

Impact: Medium Type: Content WCAG: 2.4.4 EN: 9.2.4.4

Onder de kop “Downloads” staan twee links met de tekst "download". Deze linktekst beschrijft niet duidelijk waar de link naartoe verwijst.

Wanneer meerdere links dezelfde of nietszeggende tekst hebben, is het voor bezoekers lastig om het verschil tussen deze links te bepalen. Dit kan verwarrend zijn voor bezoekers met een cognitieve beperking en voor gebruikers van een schermlezer. Schermlezers kunnen bijvoorbeeld een lijst met links tonen, waarbij meerdere keren alleen de tekst “download” wordt voorgelezen.

Dit probleem komt ook voor op de volgende pagina: https://beeldarchief.zuid-holland.nl/search.pp?pictureid=3818\&title=een-duiker-voert-waarschijnlijk-een-onderwaterinspectie-uit-bij-een-brug-of-een-sluis-de-foto-is-gemaakt-tussen-1920-en-1940.

Oplossing:

Zorg ervoor dat duidelijk is waar een link naartoe leidt, bijvoorbeeld door een tekst als ‘download’ aan te vullen met de paginatitel. Als visueel duidelijk is bij welk onderdeel de link hoort, kan deze aanvullende tekst visueel verborgen worden. Bijvoorbeeld: ‘download (Origineel afbeelding)’ of ‘download (Web afbeelding)’.

#47 - Alinea-structuur ontbreekt in de code

#48 - Links uitsluitend door kleur te onderscheiden

Op deze pagina bevat de alinea een link met de tekst “http://www.zuid-holland.nl/contact”. Het kleurverschil is het enige visuele verschil tussen deze link en de statische tekst.

Wanneer links alleen door kleur worden onderscheiden, zijn ze niet voor iedereen herkenbaar. Dit kan een probleem zijn voor gebruikers van een schermlezer.

Oplossing:

Zorg ervoor dat links in de tekst aan twee voorwaarden voldoen:

  • het contrast tussen linktekst en de omringende tekst is meer dan 3:1, en
  • voeg een tweede visuele indicator toe bij hover, zoals een onderstreping of verandering van achtergrondkleur.

Over dit onderzoek

Leeswijzer

Onze rapporten zijn anders. Bij het bespreken van de gevonden problemen volgen wij niet de structuur van de norm, maar die van jouw website of app. Hierdoor kun je gewoon per pagina of scherm aan de slag gaan. Wel zo makkelijk! Je vindt verderop een overzicht van alle pagina’s met problemen.

We geven je bij elk gevonden issue een paar voorbeelden, maar niet een complete lijst. Controleer zelf of het probleem ook nog op andere plekken voorkomt. Zie het rapport als een leidraad.

Gebruikte norm

Dit onderzoek laat zien in hoeverre de website op dit moment voldoet aan WCAG 2.2, niveau A en AA. WCAG staat voor Web Content Accessibility Guidelines. Dit is de internationale norm voor digitale toegankelijkheid. De Europese norm EN 301 549 bevat alle eisen van WCAG op niveau A en AA.

In dit rapport hebben we korte beschrijvingen van de succescriteria uit de norm opgenomen, met een algemene uitleg erbij. Wil je ze helemaal lezen? Bekijk dan de documentatie van WCAG.

Gebruikte onderzoeksmethode

We gebruiken de onderzoeksmethode WCAG-EM van het W3C. Het proces ziet er als volgt uit:

  • vaststellen wat binnen en buiten scope valt
  • vaststellen welke technologieën zijn gebruikt
  • steekproef (sample) samenstellen
  • steekproef onderzoeken
  • gevonden issues beschrijven

Het grootste deel van het onderzoek doen we met de hand. Voor een deel van de toegankelijkheidseisen gebruiken we automatische tools als ondersteuning, zoals axe-core en Chrome Developer Tools.

Belangrijk om te weten

Dit rapport helpt je om de toegankelijkheid van je website te verbeteren. Maar let op: het is geen definitieve, volledige lijst van alle aanwezige toegankelijkheidsproblemen. Dat zit zo:

Het is een steekproef

Ten eerste is het onderzoek gebaseerd op een steekproef. Die is op een betrouwbare manier genomen, en de meeste problemen zullen daardoor zeker aan het licht komen. Toch kan een probleem net buiten de steekproef vallen. Bij een volgend onderzoek kan het wel ontdekt worden.

Op basis van falsificatie

We beoordelen vanuit het principe van falsificatie. Dat houdt in dat we proberen te bewijzen dat iets niet waar is, in plaats van te bevestigen dat het klopt. ‘Voldoet’ betekent daarom dat we geen reden hebben gevonden om een punt af te keuren. Maar als we later wél een reden vinden, kan het alsnog worden afgekeurd.

Voortschrijdend inzicht

Het komt voor dat de beoordeling van een succescriterium op detailniveau verandert. De norm beschrijft namelijk niet élk mogelijk scenario. Samen met andere onderzoeksbureaus overleggen we hoe we met bepaalde situaties omgaan. Zo kan iets dat nu wordt afgekeurd, soms bij een volgend onderzoek worden goedgekeurd en andersom.

Oplossen leidt tot nieuw probleem

Ten slotte kan het gebeuren dat bij het oplossen van een probleem onbedoeld een nieuw toegankelijkheidsprobleem ontstaat. Dat komt dan bij een volgend onderzoek pas naar voren.

Hoe werkt dit rapport?

Bevindingen bekijken en filteren

Alle gevonden toegankelijkheidsproblemen staan onder Gevonden problemen. Je kunt de bevindingen filteren op:

  • Impact (Groot, Medium, Klein, Advies) — hoe ernstig is het probleem voor de gebruiker?
  • Type (Content, Techniek) — moet de inhoud of de techniek worden aangepast?
  • Status (Open, Opgelost) — welke problemen zijn al verholpen?

Voortgang bijhouden

Je kunt je voortgang op twee manieren bijhouden:

  • CSV-export — exporteer alle bevindingen als CSV-bestand en laad het in een (online) spreadsheet om met je team samen te werken.
  • Jira-export — exporteer alle bevindingen als Jira-compatibel CSV-bestand. Importeer het via Jira > Issues > Import issues from CSV. Bevindingen worden aangemaakt als bugs met prioriteit op basis van impact.
  • Registreer in de browser — activeer deze optie om per bevinding bij te houden of het is opgelost. Je voortgang wordt opgeslagen in je browser. Niemand anders kan je resultaat zien. Let op: de voortgang is gekoppeld aan je browser. Als je een andere browser of een ander apparaat gebruikt, begint de telling opnieuw.
  • Plan van aanpak — download een geprioriteerd plan van aanpak om de gevonden problemen stap voor stap op te lossen. Dit is beschikbaar bij audits vanaf maart 2026.

Link naar een specifieke bevinding delen
